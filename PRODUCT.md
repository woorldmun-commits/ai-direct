## Platform

web

## Users

Пользователи v1.0 (`docs/STRATEGY.md` §3, решение 2026-10-03) — одна платформа, три режима UX: **собственник бизнеса** («я не разбираюсь в Директе, покажите, куда уходят деньги»), **маркетолог / директолог** (несколько кабинетов, понимает метрики), **агентство** (портфель клиентов, команда, отчёт клиенту). Всем нужно быстро понять, где бюджет расходуется неэффективно или недоиспользуется, увидеть доказательство (источник, период, цифры, версия правила), спросить AI-аналитика, принять решение, внести изменение и проверить эффект.

Интерфейс послойный: сначала ответ, потом доказательства, потом инструменты. Язык — понятный собственнику; детали для специалиста — по клику.

## Product Purpose

AdPilot — независимая AI-система управления рекламой, которая говорит только проверяемую правду. Принцип **TRUTH FIRST** (STRATEGY §2): никаких выдуманных, заполненных нулём или скрытых данных; Факт → Расчёт → Вывод → Рекомендация. Обещание v1.0: подключаемся к Директу и Метрике, проверяем качество данных, находим признаки неэффективных расходов и точки роста, объясняем их на фактических данных, предлагаем действия; AI-аналитик отвечает на вопросы только из проверенных данных; изменения в кабинете вносит человек вручную. Автоматический рост эффективности не обещаем. Покупают не AI, а контроль денег клиента, доказательства и понятные действия. Оффер: «Подключите Яндекс.Директ за 2 минуты — покажем, где рекламный бюджет расходуется неэффективно».

Успех измеряется эффектом в деньгах. В v1.0 это «Сэкономлено ≈ N ₽» = конверсии после × снижение CPA, если конверсии не упали (`high_cpa_measure@2`, docs/PRD.md §1). Считается только по выполненным рекомендациям, подтверждённым сверкой по данным Директа, помечается как расчётный эффект: сравнение 7 дней до и после без контрольной группы. Формулировки «потеряно», «возвращено» и «заработано» не используются.

## Positioning

Каждый вывод проходит четыре шага: **Расход с признаками неэффективности ≈ N ₽** (оценка; одна сумма учитывается один раз) → **Почему** (причина и данные) → **Можно сэкономить ≈** (оценка с формулой и уверенностью) → **Что сделать** (конкретное действие). Каждая цифра воспроизводима по цепочке: источник → период → снимок → версия правила → рекомендация. Числа считает детерминированный код, LLM только объясняет. Кабинеты для профессионалов не копируем.

## Operating Context

- Цикл v1.0: данные → Truth Layer и Data Health → rule engine (ровно три правила: нулевые конверсии · высокий CPA · площадки РСЯ без конверсий) → доказательства и «Почему AdPilot так считает?» → рекомендация → AI-аналитик объясняет → решение человека → ручное выполнение в Директе → сверка по данным Директа → замер через 7 дней.
- Кабинет: **Анализ** (главный: итог анализа с кратким выводом AI, что изменилось, проблемы, рекомендации, доказательства, AI-аналитик) · Рекомендации · Эффект · Подключения · Настройки. **Data Health** — постоянный статус-бар сверху, не пункт меню. У каждой цифры — «Факт / Расчёт / Оценка ≈ / Недостаточно данных».
- Уведомления — без названий кампаний и клиентов.
- План до первого клиента — `docs/STRATEGY.md` §10 (≈ 9 недель).
- Вход: номер мобильного телефона + SMS-код (включается после заключения юриста, `docs/LEGAL.md`; до этого — Яндекс ID). Подключение данных: Яндекс.Директ (несколько кабинетов в workspace) и Яндекс.Метрика через OAuth.

## Capabilities and Constraints

- Стек фронтенда: Next.js 16 (App Router), React 19, Tailwind 4, lucide-react (`frontend/`). Бэкенд: FastAPI и PostgreSQL.
- Объём — `docs/STRATEGY.md` (верх иерархии) и канон `docs/VERSION_SCOPE.md`. В v1.0: чтение Директа и Метрики, Truth Layer и Data Health, аудит по трём правилам, рекомендации с «Почему AdPilot так считает?», AI-аналитик только для чтения, решение человека, ручное выполнение со сверкой, замер, агентства и роли, уведомления, бесплатный первый аудит и подписка.
- Не входят в v1.0: исполнение через Direct API, кнопка «Применить», кворум, откат через API, участие AI в действии — v1.1; CRM — v2, VK Реклама — v3, маркетплейсы — v4, автопилот — v5.
- Готовность v1.0: на живых кабинетах пилота работает повторяемый цикл находка → доказательство → решение → ручное выполнение → сверка → замер.
- Деньги — рубли с двумя знаками.
- Без решения человека в рекламном кабинете ничего не меняется; в v1.0 AdPilot в кабинет не пишет вообще.
- Биллинг честный, без тёмных паттернов (PRD §7).
- Персональные данные обрабатываются по 152-ФЗ; юридические тексты лежат в `docs/LEGAL.md` и `frontend/app/legal/`.

## Brand Commitments

- Название компании и продукта — **AdPilot**. `ai-direct` — внутреннее имя репозитория.
- Голос: факты важнее красивого ответа. Нет данных — пишем «Недостаточно данных» и что подключить. Каждый вывод — это источник, цифры и уровень уверенности.

## Product Principles

1. Сначала ответ, потом доказательства, потом инструменты.
2. Никаких выдуманных данных: каждая цифра прослеживается до источника и снимка.
3. Деньги в ₽ — главный язык интерфейса, а не метрики кабинета.
4. Решение всегда за человеком: в v1.0 продукт находит, доказывает и советует, а изменение вносит специалист вручную; AdPilot фиксирует и сверяет.
5. Честность важнее убедительности: оценка помечается как оценка, а неуверенность показывается.
