## Platform

web

## Users

Три равноправные аудитории, приоритета между ними нет:

- **Владельцы бизнеса** — малого, среднего и крупного. Не специалисты по Директу. Хотят за минуту понять, где бюджет расходуется неэффективно, почему и что сделать.
- **Маркетологи в штате.** Разбираются в рекламе. Им нужны доказательства: источник, период, цифры, версия правила.
- **Агентства.** Ведут много клиентов, и им нужна прозрачность перед заказчиком.

Интерфейс обслуживает всех троих послойно: сначала ответ (для владельца), потом доказательства (для маркетолога и агентства), потом инструменты.

## Product Purpose

AdPilot — платформа контроля рекламных расходов в Яндекс.Директе с AI-аналитиком. Покупают не AI, а контроль денег, поиск неэффективных расходов, прозрачность подрядчиков и понятные действия. Оффер: «Подключите Яндекс.Директ за 2 минуты — покажем, где рекламный бюджет расходуется неэффективно».

Успех измеряется эффектом в деньгах. В v1.0 это «Сэкономлено ≈ N ₽» = конверсии после × снижение CPA, если конверсии не упали (`high_cpa_measure@2`, docs/PRD.md §1). Считается только по выполненным рекомендациям, помечается как расчётный эффект: сравнение 7 дней до и после без контрольной группы. Формулировки «потеряно», «возвращено» и «заработано» не используются.

## Positioning

Каждый вывод проходит четыре шага: **Расход с признаками неэффективности ≈ N ₽** (оценка; одна сумма учитывается один раз) → **Почему** (причина и данные) → **Можно сэкономить ≈** (оценка с формулой и уверенностью) → **Что сделать** (конкретное действие). Каждая цифра воспроизводима по цепочке: источник → период → снимок → версия правила → рекомендация. Числа считает детерминированный код, LLM только объясняет. Кабинеты для профессионалов не копируем.

## Operating Context

- Замкнутый цикл: данные → rule engine → AI-объяснение → доказательства → рекомендация → одобрение человека (число одобрений — по уровню риска) → изменение (через Direct API с предпросмотром и откатом или вручную) → проверка через 7 дней.
- Каналы: веб-кабинет (Сегодня · Рекомендации · Аналитика · Настройки) с кнопкой «Спросить AI» (только чтение), ежедневный аудит, «что изменилось за сутки», история решений, свежесть данных и здоровье интеграций, Telegram (оповещения, утренний дайджест и недельный отчёт — без названий кампаний и клиентов).
- Вход: номер мобильного телефона + SMS-код (юридический HOLD до юриста, `docs/LEGAL.md`). Подключение данных: Яндекс.Директ (несколько кабинетов в workspace) и Яндекс.Метрика через OAuth.

## Capabilities and Constraints

- Стек фронтенда: Next.js 16 (App Router), React 19, Tailwind 4, lucide-react (`frontend/`). Бэкенд: FastAPI и PostgreSQL.
- Объём версий — канон `docs/VERSION_SCOPE.md`. В v1.0: аудит, рекомендации с блоком «Почему так решил», исполнение через Direct API с предпросмотром, одобрением и откатом, агентства и роли, «Спросить AI» (только чтение), Telegram, бесплатный первый аудит и подписка.
- Не входят в v1.0: автоматизация по заранее одобренным правилам (режимы безопасности), CRM, VK Реклама — v2.0.
- Деньги — рубли с двумя знаками.
- Без одобрения человека в рекламном кабинете ничего не меняется.
- Биллинг честный, без тёмных паттернов (PRD §7).
- Персональные данные обрабатываются по 152-ФЗ; юридические тексты лежат в `docs/LEGAL.md` и `frontend/app/legal/`.

## Brand Commitments

- Название компании и продукта — **AdPilot**. `ai-direct` — внутреннее имя репозитория.
- Голос: факты важнее красивого ответа. Нет данных — пишем «Недостаточно данных» и что подключить. Каждый вывод — это источник, цифры и уровень уверенности.

## Product Principles

1. Сначала ответ, потом доказательства, потом инструменты.
2. Никаких выдуманных данных: каждая цифра прослеживается до источника и снимка.
3. Деньги в ₽ — главный язык интерфейса, а не метрики кабинета.
4. Человек одобряет каждое изменение (критические по умолчанию — два разных участника); продукт советует и применяет только одобренное.
5. Честность важнее убедительности: оценка помечается как оценка, а неуверенность показывается.
