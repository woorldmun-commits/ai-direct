# Юридический реестр ai-direct (РФ)

Аудит 2026-10-01 по коду и документам репозитория, обновлён 2026-10-02 под PRD v1.0 и решения P0 (вход по номеру телефона + SMS-код, исполнение через Direct API, агентства и мандат агентства, «Спросить AI», Telegram без ПД). Объём версий — [VERSION_SCOPE.md](VERSION_SCOPE.md). Это рабочий чек-лист, а не юридическое заключение: тексты оферты, политики и согласий утверждает юрист. Нормы и штрафы сверены с открытыми источниками на дату аудита (ссылки внизу). Где сумма, срок или номер нормы не сверены, стоит пометка **проверить**.

## Открытые риски v1.0 — решить с юристом до запуска

| Риск | Норма | Состояние |
|---|---|---|
| **Вход по номеру мобильного телефона + SMS-код — HOLD до юриста** | ст. 10 149-ФЗ в ред. 406-ФЗ (с 01.12.2023); номер части статьи (вероятно ч. 2.1) и постановление Правительства о порядке — **проверить** | **Открытый пункт, не закрыт.** Решение продукта (PRD §4, §10 №13): вход и регистрация — российский мобильный номер (+7) и одноразовый SMS-код; email — необязательный контакт, не способ входа. Закон называет авторизацию по абонентскому номеру российского оператора одним из допустимых способов, но в порядке, установленном Правительством, и, по-видимому, с договором с оператором связи / идентификацией номера. Обычная SMS через агрегатор может этому порядку не соответствовать. **До подтверждения юристом — HOLD на запуск регистрации.** Запасной вариант с минимальной переделкой — вход через Яндекс ID (российская система авторизации; уже реализован в `auth/login.py`, код входа до отдельного PR не меняется) |
| **Основание обработки ПД сотрудников клиента** | п. 5 и п. 7 ч. 1 ст. 6 152-ФЗ | «Исполнение договора» не подходит, если клиент — юрлицо или ИП, а входит его сотрудник (он не сторона договора). Варианты: законный интерес (п. 7) или отдельное `pd_consent`. **В v1.0 при регистрации требуем оба документа** — `offer` и `pd_consent` (`REQUIRED_FOR_SIGN_UP` в `auth/login.py`), для всех пользователей одинаково. Достаточно ли этого основания для сотрудников клиента — **открытый вопрос юристу** |
| **Агентства: AdPilot — субобработчик** | ч. 3 ст. 6 152-ФЗ | Агентство, работающее через `Client-Login`, само обрабатывает данные рекламодателя по поручению; AdPilot — по его поручению. Подтверждение агентства фиксируется мандатом `agency_client_mandate` (раздел «Доказательность» ниже). Достаточно ли мандата без отдельного документа от рекламодателя — решить с юристом |
| **Изменение кампаний клиента через Direct API** | ГК (договор, ответственность), условия API Яндекса | Оферта: AdPilot меняет рекламу только после одобрения уполномоченным участником, только одобренную версию действия; журнал одобрений и исполнений (`execution_attempts`, события) — доказательство. Ограничение ответственности за результат рекламы. Проверить условия API Директа на изменение кампаний сторонним приложением |

## Роли по 152-ФЗ

| Данные | Чьи | Наша роль | Основание |
|---|---|---|---|
| Номер мобильного телефона (логин), email (необязательный контакт), сессии, участие в организации и роли, привязка Telegram (`chat_id`), IP и user agent при принятии документов | пользователь сервиса | **оператор** | договор-оферта (п. 5 ч. 1 ст. 6) для клиента-физлица; для сотрудников клиента — **см. риск выше**; рассылки — отдельное согласие |
| Статистика кабинетов, тексты поисковых запросов, цели Метрики, параметры кампаний до/после изменения | клиент и его посетители (в запросах могут встретиться ПД третьих лиц) | **обработчик по поручению клиента** (ч. 3 ст. 6); у агентства — субобработчик | поручение в оферте (состав — ниже) |
| Хэш логина Директа (лимит «1 бесплатный аудит») | владелец аккаунта | оператор | псевдонимизация, а не обезличивание — это ПД: «бессрочно» нельзя (ч. 7 ст. 5), срок — `legal_policy_defined` (п. 8), основание — п. 7 ч. 1 ст. 6 |

**Поручение в оферте (ч. 3 ст. 6)** должно содержать: цели; перечень действий с данными; меры защиты по ст. 19 и 18.1; локализацию в РФ (ч. 5 ст. 18); обязанность сообщить оператору об инциденте (ч. 3.1 ст. 21); у агентства — право клиента привлечь AdPilot.

**Обработчики по нашему поручению:** Yandex Cloud (Managed PostgreSQL, Cloud Logging, YandexGPT) — в РФ, указываются в политике. **SMS-провайдер — только российский** (иначе отправка номера — трансграничная передача, п. 2 ниже); получает номер и текст с кодом, указывается в политике; провайдер не выбран. Код хранится у нас только как хэш, TTL 5 минут. YandexGPT — не трансграничная передача; в промпт уходят только агрегаты и ID, но ID кампании ИП может быть ПД — отключить логирование запросов у провайдера (`x-data-logging-enabled: false` — **проверить** актуальный параметр).

## Доказательность принятия и мандат агентства

- **`legal_acceptances`** — реализовано в коде и схеме: `document_sha256` (sha256 точного текста версии), `locale`, `ip` (inet), `user_agent` (≤ 256 символов). Реестр версий и хэшей — `app/legal/documents.py` (`VERSIONS`), тексты — `app/legal/texts/<документ>/<версия>.<locale>.md`; опубликованная версия не правится, новый текст = новая версия. Сейчас тексты — заглушки, их утверждает юрист. IP и user agent скрыты от прикладной роли и обнуляются через 30 дней после деактивации; при удалении пользователя принятия обезличиваются (выше). Срок хранения обезличенных доказательств — **открытый вопрос юристу** (п. 8).
- **Мандат агентства `agency_client_mandate`.** При добавлении клиента агентство подтверждает: есть право передавать данные клиента в AdPilot; клиент поручил обработку рекламных данных; есть право предоставлять AdPilot доступ к Директу клиента. Запись — `legal_acceptances` с документом `agency_client_mandate` и `workspace_id`, append-only, пишется при добавлении клиента (не при регистрации: в `login.DOCUMENTS` мандата нет). Без неё workspace агентства не подключает Директ **[v1.0]**. Текст мандата утверждает юрист.

## До запуска: не код, но без этого штраф

Порядок — по риску. Штрафы указаны для юрлица или ИП в редакции КоАП с 30.05.2025.

1. **Уведомление РКН о начале обработки ПД** (ст. 22) — до первой регистрации пользователя. За неподачу — до 300 тыс. ₽.
2. **Уведомление РКН о трансграничной передаче** (ст. 12, ч. 3): Telegram — иностранная компания и серверы за рубежом, а `chat_id`, связанный с пользователем, — ПД. Подать до запуска Telegram-уведомлений, собрав сведения о получателе (ч. 5 ст. 12). SMS-провайдер — российский, чтобы номер телефона в это уведомление не попадал. Для стран без «адекватной» защиты (ОАЭ / BVI, по-видимому, не в перечне — приказ РКН № 128, **проверить**) передача начинается не раньше чем через **10 рабочих дней** после подачи, если РКН не запретил. **Тексты Telegram — без ПД и без данных клиента:** нет названий клиентов, кампаний, поисковых запросов, логинов; только тип события, сумма и ссылка («🔴 Новая проблема · Расход с признаками неэффективности ≈ 18 400 ₽ · Открыть AdPilot»), подробности — после входа. Недельный отчёт — агрегаты без названий. За рубеж уходят `chat_id` и текст без названий и ПД; уведомление РКН всё равно нужно. Email-провайдер и прочие подрядчики — российские; иначе каждый тоже попадает в это уведомление.
3. **Политика обработки ПД** опубликована на сайте (ч. 2 ст. 18.1). Её содержание — таблица хранения из ARCHITECTURE.md §2.5, роли и обработчики из этого файла.
4. **Оферта с поручением на обработку** (ч. 3 ст. 6, состав — выше) и условия исполнения через API (риск выше). Отдельно — **согласие на рекламные рассылки** (ч. 1 ст. 18 38-ФЗ; документ `marketing`, по умолчанию не выбран). Отдельное **согласие на обработку ПД** (`pd_consent`) в v1.0 обязательно при регистрации вместе с офертой; достаточность основания для сотрудников клиента — риск выше. Отдельный документ требуется с 01.09.2025, штраф до 700 тыс. ₽.
5. **Процесс инцидентов:** уведомить РКН об утечке **за 24 часа**, результаты расследования — за 72 часа (ч. 3.1 ст. 21). За неуведомление — 1–3 млн ₽. Сама утечка — от 3 млн ₽ (1–10 тыс. субъектов) до 15 млн ₽; при повторной — оборотный штраф. Назначить ответственного, расписать, кто и за сколько часов действует. Как обработчик — сообщать клиенту-оператору.
6. **Внутренние документы оператора** (ст. 18.1, 22.1): ответственный за ПД, приказ о мерах защиты, оценка вреда, уровень защищённости ИСПДн (ПП РФ № 1119). Это бумаги, но РКН проверяет их первыми.
7. **Запросы субъектов** (ст. 14, 20, 21):
   - ответ и ознакомление — 10 рабочих дней, продление на 5 с мотивированным уведомлением (ч. 7 ст. 14, ч. 1 ст. 20);
   - уточнение или уничтожение, если субъект подтвердил неточность или незаконность, — **7 рабочих дней** (ч. 3 ст. 20);
   - прекращение незаконной обработки — **3 рабочих дня**, уничтожение — 10 рабочих дней (ч. 1, 3 ст. 21);
   - прекращение обработки по требованию — 10 рабочих дней (ч. 5.1 ст. 21); отзыв согласия — уничтожение за 30 дней (ч. 5 ст. 21);
   - запрос РКН — 10 рабочих дней + 5 (ч. 4 ст. 20);
   - запросы о данных клиента (мы обработчик) — передавать клиенту-оператору.
8. **Удаление данных:**
   - бухгалтерские документы B2B-клиентов (счета, акты) — не менее 5 лет (ст. 29 402-ФЗ, ст. 23 НК); удаление аккаунта их не затрагивает, в `deletion_requests.verification` — «хранится по закону до <дата>» (основание п. 2 ч. 1 ст. 6);
   - **сроки класса `legal_policy_defined` (ARCHITECTURE.md §2.5) не утверждены**: 152-ФЗ требует хранить ПД не дольше, чем нужно для целей обработки, если иной срок не установлен законом или договором (ч. 7 ст. 5). Предварительно рассматривается 3 года для обезличенных `legal_acceptances` (после закрытия аккаунта; исковая давность, ст. 196 ГК) и для хэша логина Директа (с отметки о бесплатном аудите), но срок не считается утверждённым до юридической проверки. До утверждения записи не удаляются автоматически; `delete_workspace_data` `legal_acceptances` не удаляет; при удалении пользователя они обезличиваются (`user_id`, `ip`, `user_agent` → NULL), `ip` / `user_agent` — обнуляются через 30 дней после деактивации;
   - после восстановления из бэкапа удаления повторно применяются по журналу `deletion_requests`;
   - **акт об уничтожении ПД и выгрузка из журнала** — по приказу РКН № 179, хранить 3 года. Вероятно, акт должен идентифицировать субъектов (**проверить**) — тогда это противоречит принципу «журнал удаления без ПД»; решить форму с юристом;
   - логи с IP и ID пользователей — тоже ПД: 30 дней, указать в политике.
9. **Сайт и cookie:** Яндекс Метрика на лендинге загружается только после согласия, а ссылка на политику стоит в баннере. Баннер «продолжая пользоваться…» сам по себе не защищает.
10. **Подписки (376-ФЗ, ЗоЗПП):** Федеральный закон от 15.10.2025 № 376-ФЗ добавил п. 4.2 ст. 16.1 ЗоЗПП, действует **с 01.03.2026**: нельзя списывать периодические платежи с реквизитов, от использования которых потребитель отказался; отказ нужно принимать, в том числе в электронной форме. Закон защищает потребителей (юрлица и ИП для бизнеса — вне его), но фрилансер с личной картой может им оказаться — **применяем правило ко всем**. Реализация — DATA_MODEL.md §7: `payment_method_refused_at`, канал отказа, событие `payment_method_refused`, проверка воркера перед каждым списанием, удаление способа у провайдера, `payer_type`, версия текста согласия. Отказ от способа оплаты ≠ отмена подписки. Уведомление за 3 дня до списания — наш выбор, а не требование 376-ФЗ (**проверить**). Отмена — простая, в кабинете. Онлайн-чек по 54-ФЗ — через кассу провайдера: проверить, что она включена в договоре.
11. **Своя реклама** (38-ФЗ): объявления в интернете маркируются (erid, отчёт через ОРД). За нарушение — штраф до 500 тыс. ₽ (**проверить**, ст. 14.3 КоАП). Не обещать результат: «Сэкономлено ≈ N ₽» всегда с пометкой «оценка» и формулой. Вместо «потеряно / потери» везде — «Расход с признаками неэффективности ≈ N ₽» (оценка, одна сумма учитывается один раз); на лендинге — «Показываем, где рекламный бюджет расходуется неэффективно». Это **наша мера снижения риска** вводящих в заблуждение утверждений — ст. 5 38-ФЗ требует достоверности рекламы, но таких формулировок дословно не предписывает. «Найдём все потери» и «вернём деньги» в рекламе не писать.
12. **Условия API Яндекса:** заявка на доступ к API Директа и регистрация приложения. Проверить, требует ли Яндекс ссылку на политику конфиденциальности, ограничивает ли передачу полученных данных третьим лицам (LLM — YandexGPT, внутри Яндекса) и разрешает ли изменение кампаний сторонним приложением по одобрению пользователя.

## Когда менять этот файл

Новый подрядчик, хранилище, канал уведомлений или страна → строка в ARCHITECTURE.md §2.5 и пункт 2 выше **до** запуска. Новый документ для принятия → значение в `legal_acceptances.document`, версия в реестре `app/legal/documents.py` (`VERSIONS`) и файл текста (из него `document_sha256`); в `login.DOCUMENTS` — только документы, принимаемые при регистрации. Мандат агентства (`agency_client_mandate`) в `login.DOCUMENTS` не добавляется: он пишется при добавлении клиента. Новая редакция текста — новая версия, а не правка файла. Новый способ входа или SMS-провайдер → пересмотреть риск 149-ФЗ и пункт 2.
