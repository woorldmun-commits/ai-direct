# Закрытый пилот: допуск и шаблон клиентского отчёта

Рабочий документ для concierge-пилота (цель — 2026-10-13). Не заменяет договор: тексты договора, мандата агентства и политики ПД утверждает юрист ([LEGAL.md](LEGAL.md)). Пилот — разовый аудит кабинета скриптом `backend/scripts/e2e_account.py` и отчёт; самообслуживания, синхронизации по расписанию и уведомлений в нём нет.

## 1. Условия допуска (все пункты — «да», иначе только демо на безопасных данных)

| № | Условие | Подтверждение (кто, когда) |
|---|---|---|
| 1 | Доступ к API Директа **фактически получен** (не «заявка подана»): токен с `direct:api` и `metrika:read` | |
| 2 | Договор пилота подписан: поручение на обработку (ч. 3 ст. 6 152-ФЗ), «рекомендации ≠ гарантия результата», «только чтение», срок | |
| 3 | Для агентства: мандат на доступ к кабинету клиента (`agency_client_mandate`) подписан | |
| 4 | Порядок передачи токена, хранения артефактов и **удаления данных / отзыва доступа** согласован в договоре; срок удаления указан | |
| 5 | Прогон `e2e_account.py` выполнен на реальном кабинете, статус `PASS` или `REVIEW`; `FAIL` — отчёт не отправляется | |
| 6 | **Каждая** рекомендация проверена вручную по разделу 3 и отмечена «подтверждена» / «исключена» / «с оговоркой» | |
| 7 | Клиенту не обещаны: автосинхронизация, уведомления, управление рекламой, доказанная экономия | |

## 2. Прогон

```
set YANDEX_API_TOKEN=...            (в окружении; не в чат, не в файл)
python scripts/e2e_account.py --login <client_login> --counter <id> [--goals 111,222] [--target-cpa 3000]
```

Артефакты `<out>/<время>/run.json` и `summary.txt` содержат хэш логина и id кампаний (названий нет). Хранить на зашифрованном диске, не пересылать в мессенджерах, удалить по сроку договора.

## 3. Ручная проверка каждой рекомендации

Для каждой находки специалист AdPilot отвечает письменно:

- [ ] Расход и конверсии за период совпадают с кабинетом Директа/Метрики (сверка 2–3 цифр глазами).
- [ ] Цель конверсии выбрана верно (не «любая цель»); для автостратегий / ЕПК учтён период обучения.
- [ ] Период и окно данных достаточны (пороги — PRODUCT_SPEC §9.1); данные за последние дни могут уточниться.
- [ ] Формула пересчитывается вручную и даёт ту же сумму.
- [ ] Нет двойного учёта: сумма по пересекающимся находкам не складывается (итог — `exposure_total`).
- [ ] Вывод не противоречит контексту клиента (сезон, акция, изменение бюджета, остановка кампании).

Итог по находке: **подтверждена** (идёт в отчёт) · **с оговоркой** (идёт с пометкой «требует проверки») · **исключена** (не идёт, причина записана).

## 4. Шаблон отчёта клиенту

> **Отчёт по аудиту рекламного кабинета Яндекс Директ**
> Клиент: ______ · Период данных: __.__.____ – __.__.____ · Дата отчёта: __.__.____ · Источники: Яндекс Директ, Яндекс Метрика (только чтение)

**1. Итог.** Расход с признаками неэффективности ≈ ______ ₽ (**оценка**, одна сумма учитывается один раз). Проверено кампаний: __; правил: 3 (нулевые конверсии · высокий CPA · площадки РСЯ без конверсий); найдено проблем: __, подтверждено специалистом: __.

**2. Находки** (по одной на блок):

| Поле | Содержание |
|---|---|
| Что | заголовок находки |
| Факты | расход, конверсии, CPA — каждое число с периодом и источником («Факт» / «Оценка ≈» / «Недостаточно данных») |
| Как посчитано | формула и правило с версией (например, `high_cpa_target@1`) |
| Уверенность | высокая / средняя / низкая и почему |
| Проверка специалистом | подтверждена / с оговоркой (в чём) |
| Что можно сделать | действие, которое **выполняете вы** в кабинете; AdPilot ничего не меняет |

**3. Где данных недостаточно.** Перечень правил/кампаний со статусом «Недостаточно данных» и что подключить или дождаться (например, цель Метрики, ещё 7 дней данных). Нулей вместо отсутствующих данных в отчёте нет.

**4. Что в отчёте не обещано.** Это оценка по данным за период, а не гарантия экономии или роста. Эффект изменений можно измерить только после их внесения (сравнение до/после без контрольной группы — признак эффекта, не доказательство).

**5. Данные и доступ.** Доступ только на чтение. Отозвать доступ и потребовать удаления данных можно в любой момент в порядке, указанном в договоре: ______.

## 5. Что не выполняется в пилоте (не обещать)

Автоматическая синхронизация по расписанию · уведомления (в интерфейсе, email) · личный кабинет и вход · оплата · изменение рекламы через API · «доказанная» экономия.
