# Внедрение рекомендаций Rekvero — 18.10.2026

Рабочая версия: `designe 1.0`, backend — `backend`. Это локальная проверка, не допуск production. Изменения других задач сохранены, коммит и публикация не выполнялись.

## Реализовано

1. Паспорт рекомендации: источник и период каждого Value, объект, проверенные инструкции, текущая версия, история. Ручные решения reject/postpone/check и заявление о выполнении защищены ролью, RLS, актуальностью состояния и идемпотентностью. Ручная отметка не подтверждает изменение в Директе.
2. Проверки выбранных аккаунтов: доступность Директа/Метрики, свежесть снимков, наличие определения целей. Наличие определения не доказывает корректность цели. Единого выдуманного «балла здоровья» нет.
3. План бюджета и фактический расход за тот же полностью покрытый период. Отклонение — факт минус пользовательский план; экстраполяции и автоматического изменения бюджета нет.
4. CSV со стабильными UUID, датами и статусами: атомарная проверка, повтор без дублей, обновление статуса, запрет контактных полей и чужих аккаунтов на API и DB уровнях. До 500 строк и 48 000 байт. UUID — псевдоним, не гарантия анонимности.
5. qCPL: сопоставление периода привлечения, аккаунтов, расхода и квалификации. Полнота когорты — явное заявление пользователя. Неизвестные данные оставляют показатель недоступным. Опциональные суммы заявок не выдаются за подтверждённую выручку или прибыль.
6. Сводка по запросу: детерминированные факты и ограничения. Автоматической рассылки пока нет.
7. [Проектная команда](../project-agents/README.md): роли, ответственность и руководитель проверки доказательств. Исполняемый `python -m app.agents verify claims.json --evidence trusted-manifest.json` сверяет весь контекст Value с независимо предоставленным manifest. Произвольный JSON не становится доказательством: `authenticity_verified:false`. Профили не запускают фоновые LLM-процессы.

## Защита и эксплуатация

Закрытый BFF разрешает только перечисленные пути, требует сессию и доверенный Origin для POST, ограничивает тела и ответы, не передаёт лишние cookies и запрещает кэширование. Новый `REKVERO_APP_ORIGIN` задаёт адрес браузерного сайта, когда Next.js работает за reverse proxy с внутренним hostname. Он должен совпадать с реальным публичным origin и backend `API_ALLOWED_ORIGINS`. Forwarded-Host не используется как основание доверия. Некорректная конфигурация закрывает доступ.

Новая миграция 0006 добавляет tenant-таблицы планов и заявок; её SQL совпадает с canonical schema, контрольная сумма внесена в released.txt. Для существующей БД требуется штатное применение миграций; локальная проверка не применяет их к production.

## Проверки

- Полный backend: **1 648 passed**, одно предупреждение Starlette/httpx о deprecated test client.
- Миграции проверены на эквивалентность canonical schema; роли, RLS, чужие аккаунты, удаление workspace, Decimal, неполные когорты и повторные решения входят в тесты.
- Build, TypeScript, ESLint и контрактные проверки BFF/Value/паспортов прошли. Исправления интерфейса проверяются production-сборкой, а не только dev-сервером.
- Браузер: реальный локальный FastAPI + отдельная PostgreSQL с синтетическими аккаунтами. Проверяются SSR, обновление бюджетного плана через BFF, конкретные инструкции, CSRF, отсутствие сессии в HTML, no-store/noindex и ширины 1440/834/390/320. Итоговый результат и снимки: `designe 1.0/artifacts/insights/`.
- Независимый review обнаружил и помог исправить свободные regex идентификаторов/хэшей и отсутствие конкретных инструкций. Браузер обнаружил и помог исправить mismatch публичного/internal Origin и отсутствие обновления SSR после перехода по якорю.

## Открытые работы — не обозначать как готовые

| Работа | Что осталось |
|---|---|
| Собственный вход email/password | Пользователь выбрал ИП; [правовая проверка](2026-10-18-email-password-rf.md). Нужны подтверждение условий владельца, проверка почты, восстановление, защита перебора, инфраструктура и почтовый подрядчик. Текущий вход — Яндекс ID. |
| Онлайн-подписки | Провайдер не выбран. Нет production checkout, webhooks, чеков, сверки платежей и согласованных серверных тарифных прав. |
| CRM API и телефония | Импорт CSV работает; внешние Bitrix24/amoCRM/calltracking ещё не подключены. Нужны конкретные системы, поля, права и обработка данных. |
| Автоматическая сверка выполнения | Endpoint явно возвращает unavailable; worker и сохранение подтверждений отсутствуют. Замер без сверки не включается в подтверждённую экономию. |
| Сводки по расписанию | Только отчёт по запросу. Планировщик, доставка, согласия и обработка сбоев не реализованы. |
| Публичный запуск | Нужны реквизиты ИП, утверждённые документы, российское размещение и резервирование, production OAuth/домен/DB, проверка реальных кабинетов, нагрузки и восстановления. |

Новые рекламные правила, автоматическое изменение Директа и обещания роста дохода не добавлялись. Три действующих правила не заменены большим количеством номинальных «агентов».
