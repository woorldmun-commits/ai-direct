## Замечания, переданные исполнителям

1. **HIGH, условие допуска регистрации: видимый текст должен соответствовать согласию.** На проверенном снимке `frontend/components/reference/auth.tsx:23` отправляет принятие `offer` / `pd_consent` версии `2026-10-01`; ссылки ведут на `frontend/app/legal/[slug]/page.tsx:35`, где показан только статус отсутствия утверждённого текста. Сценарий: администратор задаёт хэши backend документов → регистрация разрешена → посетитель принимает документ, полного текста которого ему не показывают. Существующая `_approved` в `backend/app/api/auth.py:53` проверяет серверный хэш, но не содержание frontend страницы. До исправления нельзя включать регистрацию одним добавлением хэшей. Backend и frontend исполнители сообщили, что реализуют общий источник точных текстов и отображение доступности.

2. **MEDIUM, несогласованный путь подключения.** `frontend/components/reference/landing.tsx:11`, `:42`, `:49` обещают раздел подключений / настройки. Фактический `frontend/app/workspace/page.tsx` содержит выбор пространства, метрики и рекомендации, но не управление источниками. `frontend/components/reference/auth.tsx` правильно сообщает, что подключением занимается администратор. Сценарий: клиент входит по инструкции с лендинга → не находит обещанный экран → не может выполнить первый шаг. Минимум: выровнять инструкции под подключение администратором; self-service требует отдельной реализации. Parent взял исправление формулировок.

3. **Конфигурационный blocker, canonical домен.** На проверенном снимке `frontend/lib/site.ts:2` фиксирует `https://adpilot.ru`, хотя владение доменом не подтверждено. Этот адрес попадает в metadata, sitemap и robots. Перед публикацией нужен подтверждённый публичный origin. Parent взял конфигурацию домена.

4. **Конфигурационные blockers владельца.** Отсутствуют реальные OAuth приложения и права провайдера, production БД с прикладной ролью/RLS, оператор и утверждённые документы. Их нельзя заменить тестовыми значениями, демонстрационными метриками или скрытием предупреждений.

5. **MEDIUM, обещанные показатели шире рабочего кабинета.** `frontend/components/reference/landing.tsx:45` обещает «Расходы, конверсии и CPA», но проверенный `frontend/app/workspace/page.tsx` и контракт `PilotToday` отображают расход, оценку расхода с признаками неэффективности и число рекомендаций. Сценарий: подключённый клиент ожидает CPA из лендинга → этот показатель в рабочем экране отсутствует. Наличие расчётов в других внутренних модулях не делает их частью этого UI. Parent уведомлён: минимальное исправление — выровнять публичные формулировки под фактически доступный экран.

## Что проверено по исходникам

- `frontend/lib/pilot.ts`: `server-only`, сессия читается на сервере, доверенный API origin, ограниченный список путей, `no-store`, timeout, проверка JSON и контракта; нет fallback на синтетическую статистику.
- `frontend/lib/auth-proxy.ts`: allowlist методов/путей/cookies, Origin для POST, ограничение размеров тела, upstream redirect manual, разрешены только локальные переходы `/workspace` и `/login`, credentials не направляются в адрес клиента. Поздняя правка добавила таймаут чтения потока; она требует повторного прогона тестов исполнителем после финального изменения.
- `backend/app/api/auth.py`: flow cookie Fernet с TTL 600, state проверяется до обмена кода, HttpOnly/SameSite и Secure для HTTPS, approval проверяется повторно на callback, logout удаляет серверную сессию.
- `backend/app/api/deps.py`: actor только из действительной сессии активного пользователя; доступ к workspace через членство; чужой workspace не читается по одному ID.
- `backend/app/api/db.py`: API принимает только роль `app_rw` без superuser/BYPASSRLS; запрос работает в транзакции, локальный workspace очищается; reset отвергает утечку контекста.
- `backend/app/api/middleware.py`: Origin CSRF, ограничение тела, ошибки без traceback клиенту, запрет кеширования и security headers.
- `frontend/proxy.ts` и `next.config.ts`: per-request nonce CSP, защита от embedding, nosniff, Permissions Policy, HSTS. Проверка кода не подтверждает реальные заголовки reverse proxy/CDN.
- Legacy `/demo` закрыт redirect из layout; `/prisma-preview` направляется на главную. Старые fixture-модули в исходниках сами по себе не являются публичным демо, если недостижимы из production routes.
- Рабочий кабинет явно показывает read-only режим, состояние недостатка данных, свежесть, ограничения расчёта и запрет суммирования пересекающихся карточек. Полные доказательства/решения/сверка HTTP пока не представлены; UI это раскрывает.

## Проверки, выполненные этим ревьюером

Дополнительный просмотр backend после исправлений: `backend/app/api/legal.py` ограничивает документ реестром, версию — опубликованными версиями, locale — `ru-RU`, отдаёт точные байты текста и их SHA256. Callback создаёт организацию и пространство только для `signed.user_id` нового пользователя, через существующие SQL функции с проверкой active/manager. Новых подтверждённых HIGH/CRITICAL дефектов в этих правках не найдено. Полный backend прогон и интеграция frontend правовых страниц выполняются другими участниками; их результат здесь не присваивается.

## Условия допуска владельцем

Нужны подтверждённый домен/HTTPS и origin; хостинг и секреты вне клиентского bundle; production БД/миграции и проверенное восстановление backup; реальные provider approvals и OAuth callback; утверждённые точные тексты и реквизиты; проверка входа/выхода/отзыва доступа на реальном окружении; настроенные лимиты и наблюдаемость ingress; финальные build, test и browser результаты на одном финальном снимке. Доступность платного биллинга, автоматических рекламных изменений и LLM не заявлять до их отдельной проверки.

Не проводились атаки на внешние системы, реальные OAuth/ad writes, production нагрузка, проверка инфраструктуры и юридическое заключение. Запуск без этих проверок и данных владельца остаётся риском; данный отчёт не является разрешением production.
