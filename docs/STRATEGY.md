# Стратегия INROU — v1.0

> Текущий статус реализации, 28.10.2026: email/password, подтверждение почты и восстановление пароля реализованы; их включение требует реального отправителя и утверждённых документов. Директ/Метрика, очередь, ручные решения и детерминированный анализ реализованы. Другие каналы и внешняя LLM не подключены; сверка действия ограничена поддержанными сценариями, биллинг требует отдельной приёмки. Состояние поставки — [RELEASE_STATUS.md](RELEASE_STATUS.md), ограничения — [COMMERCIAL_STATUS.md](COMMERCIAL_STATUS.md), условия реального пилота — [LAUNCH_READINESS.md](LAUNCH_READINESS.md). Исторические решения ниже сохраняются с датами.


> **Решение владельца продукта 2026-10-21 (расширение):** оба сегмента, четыре группы каналов поэтапно (Директ + Метрика → коллтрекинг и CRM → VK Реклама → Авито), сервис только советует, нейросеть оценивает тексты объявлений с пометкой «мнение», 7 дней бесплатно + три тарифа. Поэтапный план — [§9](#9-расширение--решение-владельца-2026-10-21). Где §2–§5 ниже расходятся с §9, прав §9.

> Решение владельца продукта 2026-10-02 (сужение v1.0). **Верх иерархии решений по объёму и правилам:** изменение объёма версий или списка правил аудита начинается с правки этого файла, затем — [VERSION_SCOPE.md](VERSION_SCOPE.md) и [PRD.md](PRD.md). Решения P0 (D2–D18) действуют, кроме объёма: исполнение (D5–D8) перенесено в v1.1.

## 1. Тезис

INROU — **доказательный контроль рекламного кабинета с обязательным решением человека**.

Не «AI решит за вас», а «INROU обнаружит проблему, докажет её на данных и проведёт решение через человека».

**Обещание v1.0:** сервис выявляет риски и возможности в кабинете Яндекс.Директа, объясняет их и помогает принять контролируемое решение. Изменения в кабинете вносит человек вручную; INROU фиксирует решение, сверяет выполнение по данным Директа и измеряет эффект. Автоматический рост эффективности не обещаем.

## 2. Сегмент и работа пользователя

**Сегмент v1.0:** малые агентства и самостоятельные директологи — у одного специалиста несколько кабинетов, он понимает метрики, а агентство — канал к собственникам бизнеса. Один сценарий, не два продукта: собственник бизнеса — не целевой сегмент v1.0, его сценарии позже.

**С 2026-10-21:** целевые сегменты — оба: агентства и директологи, а также собственники малого бизнеса (§9.1). Пилот v1.0 по-прежнему идёт на агентствах.

**Работа пользователя:** быстро понять, где бюджет расходуется неэффективно или недоиспользуется → увидеть доказательство → принять решение → вручную внести изменение в Директе → проверить эффект.

## 3. Ровно три правила v1.0

> 1. **Нулевые конверсии** — расход без конверсий при достаточном объёме данных.
> 2. **Высокий CPA** — CPA выше целевого (или базового) при достаточном числе конверсий.
> 3. **Площадки РСЯ без конверсий** — площадки сетей с расходом и без конверсий.
>
> Рекомендации должны работать и в мире автостратегий и ЕПК: ценность не зависит только от «снизить ставку» (рычаги: цель CPA, качество конверсий/цели, минус-фразы, исключение площадок, корректировки, контроль изменений). Новое правило в v1.0 не добавляется без изменения STRATEGY.md.

Это критерий решений: функция, которая не помогает найти, доказать, решить или проверить одну из трёх проблем, в v1.0 не попадает.

Список правил после v1.0 расширяется только по этапам §9.2: каждое новое правило — отдельная версия `@1` с порогами, утверждёнными владельцем, и golden-кейсами в `backend/evals/`.

## 4. Объём v1.0

**Входит:**
- подключение и чтение данных: Директ (N кабинетов в workspace), Метрика; агентства, роли организации и workspace (D3, D4);
- снимки данных, аудит по трём правилам, приоритизация, итог «Расход с признаками неэффективности ≈ N ₽» без двойного учёта (D9);
- доказательства и «Почему INROU так решил» — AI только объясняет конкретную рекомендацию, claims → evidence, непрозрачные ссылки (D11);
- рекомендация → решение человека → ручное выполнение и его фиксация → сверка по данным Директа (чтение) → замер эффекта (D10);
- вход и регистрация по российскому мобильному номеру + SMS-код (D2);
- уведомления в интерфейсе INROU и email-дайджест без названий клиентов, кампаний и запросов (D15);
- бесплатный первый аудит + подписка;
- RLS и изоляция (D13), юридическая доказательность (D16), DR (D17), evals для правил и политик (D12), наблюдаемость (D18).

**Не входит:**
- любое исполнение изменений через API рекламных систем (ставки, бюджеты, цели, минус-фразы, площадки, статусы), массовое применение, UX «Применить одним кликом»;
- откат как механизм исполнения, предпросмотр «было → станет» для применения, кворум одобрений по риску;
- общий AI-чат «Спросить AI», автономные агенты, сложная AI-оркестрация;
- CRM, VK Реклама, Outcome Graph как модуль (CRM, коллтрекинг, VK Реклама и Авито — этапы 2–4 §9.2).

Подробный перечень — [VERSION_SCOPE.md](VERSION_SCOPE.md).

## 5. Направление v1.1

> **Отложено решением 2026-10-21:** сервис только советует, API-исполнение не планируется (§9.1). Описание контура ниже сохранено как проект; номер v1.1 теперь занят этапом 1 §9.2.

Безопасное API-исполнение — отдельный, явно спроектированный контур, а не кнопка поверх v1.0. Включается только после проработки:
- прав доступа (запись в Директ, роли, `Client-Login` агентства);
- idempotency операций;
- лимитов (на объём изменений и частоту);
- журнала операций;
- approval flow: риск → кворум одобрений;
- предусловия, проверки после записи и безопасного отката.

Проект контура — [EXECUTION_SAFETY.md](EXECUTION_SAFETY.md) и [API_CONTRACT_EXECUTION.md](API_CONTRACT_EXECUTION.md). Начинаем с 1–2 обратимых действий низкого или среднего риска.

Также v1.1: квалификация лидов и офлайн-конверсии (CSV) — сразу после базового среза; «Спросить AI» только в режиме чтения; Web Push (VAPID) как канал критичных уведомлений; SMS-напоминание о критичной находке по согласию пользователя; альтернативные способы входа (Яндекс ID, VK ID) — только как резерв, не как основной.

v2.0: Outcome Graph, обучение на исходах, автоматизация по заранее одобренным правилам (отложена вместе с исполнением). CRM и VK Реклама перенесены в этапы §9.2.

История «рекомендация → решение → изменение → результат» собирается с первого дня v1.0 — это основа для v1.1 и v2.0.

## 6. Пилот: метрики и критерий успеха

| Метрика | Что показывает |
|---|---|
| Time to first finding | время от подключения до первой находки |
| Recommendation acceptance rate | доля рекомендаций, принятых к ручному выполнению |
| Rejection reasons | причины при «Не буду»: неверные данные · нерелевантное правило · недостаточно контекста · слишком рискованно · другое |
| False-positive rate | доля находок, которые специалист счёл ложными |
| Free-to-paid conversion | переход с бесплатного аудита на подписку |
| Подтверждённый результат | есть ли хотя бы один измеренный результат после ручного изменения |

**Пилот:** 10 агентств / кабинетов.

**Успех:** специалисты получают понятные находки, используют часть рекомендаций и видят ценность, достаточную, чтобы продолжить или платить. Критерий — повторяемый полезный цикл на живых кабинетах, а не число экранов.

## 9. Расширение — решение владельца 2026-10-21

Основание — исследование 21.10.2026 трёх направлений: API площадок, рынок и конкуренты, право. Отчёты в репозиторий не сохранены; ниже — выводы с метками **[факт]** (сверено с официальной документацией) и **[не проверено]**. Это не юридическое заключение.

### 9.1 Решения

| Вопрос | Решение |
|---|---|
| Сегмент | Оба: агентства и директологи, собственники малого бизнеса |
| Боль 1 | Бюджет уходит впустую: где расход без результата, ≈ сколько ₽, по каким данным, что поправить |
| Боль 2 | Теряются клиенты: обращения пришли, но без ответа или с поздним ответом. Показывается **в штуках и минутах, не в ₽** — денежной оценки без данных о выручке нет (ECONOMICS) |
| Действия | Только советует. В рекламные кабинеты ничего не пишет; API-исполнение (§5) отложено |
| Нейросеть | Объясняет рекомендации и оценивает тексты и картинки объявлений — с явной пометкой «мнение». Чисел не считает и не вводит |
| Выдача | Веб-кабинет |
| Оплата | 7 дней бесплатно, затем подписка: Старт — 2 000 ₽/мес, Бизнес, Премиум. Состав и цены Бизнеса и Премиума не утверждены |
| Каналы | Директ + Метрика, коллтрекинг и CRM, VK Реклама, Авито — по этапам §9.2 |

### 9.2 Этапы

Каждый этап входит в работу только при выполнении условия входа. Нет данных для проверки — «Недостаточно данных» и что подключить.

| Этап | Версия | Что | Условие входа |
|---|---|---|---|
| 0 | v1.0 | Три правила §3, пилот на агентствах | текущий план §7 |
| 1 | v1.1 | Директ + Метрика «досконально» (таблица ниже), оценка текстов объявлений нейросетью, 7 дней бесплатно и тарифы | пороги каждого правила утверждены владельцем; правка AI_GOVERNANCE под «мнение» |
| 2 | v1.2 | Коллтрекинг (Calltouch, UIS/CoMagic) и CRM (amoCRM, затем Битрикс24): пропущенные звонки, время ожидания, заявки без ответа, время до первого контакта | позиция юриста по ролям и поручению (152-ФЗ), подтверждённое хранение в РФ, прочитаны условия API каждой системы |
| 3 | v1.3 | VK Реклама: проверки этапа 1 на статистике VK | одобрен поток Authorization Code для сторонних сервисов (включается только по запросу в поддержку VK) **[факт]** |
| 4 | v1.4 | Авито: платное продвижение без роста контактов, чаты без ответа | прочитаны официальная документация и условия API Авито; известно, какие тарифы продавца дают доступ (по сторонним данным, мессенджер — только на платных тарифах) **[не проверено]** |

**Проверки этапа 1** — кандидаты; каждая становится правилом только после утверждения порогов.

| Срез | Проверка | Данные |
|---|---|---|
| Поисковые запросы | Запросы с расходом без конверсий — кандидаты в минус-фразы | Директ, отчёт SEARCH_QUERY **[факт]** |
| Ключевые фразы | Фразы с расходом без результата | Директ, отчёт по условиям показа **[факт]** |
| Объявления | Явный аутсайдер внутри группы по CTR и CPA | Директ, отчёт по объявлениям; нужен статистический порог |
| Поиск и сети | Перекос CPA между поиском и РСЯ | Директ, `AdNetworkType` **[факт]** |
| Аудитории | Пол, возраст, устройства, регионы, время с расходом без конверсий | Директ, Custom report; названия полей сверить **[не проверено]** |
| Настройки | Цель не срабатывает; стратегия на цель без конверсий; отклонённые объявления; нет расширений; нет UTM; битые ссылки | Директ `Ads`/`Campaigns.get`, Метрика Management |
| Качество трафика | Отказы и визиты короче 15 с по кампаниям и посадочным | Метрика Logs API **[факт]**; в сырых данных есть ClientID и IP — брать только агрегаты |
| Тексты объявлений | Оценка заголовков и текстов, предложения улучшений — «мнение» | YandexGPT, логирование запросов выключено |

**Для этапа 2 берём только метаданные:** событие, время, длительность, отвечено или нет, время до ответа, кампания, этап сделки. **Не берём:** записи звонков, транскрипты, тексты сообщений, ФИО и комментарии из CRM.

**Не подключаем:** Яндекс Карты, 2ГИС, Telegram Ads — официального API не найдено; отзывы без официального API не собираем. Wordstat — только как контекст, без находок в ₽. Свою телефонию, чат-боты и речевую аналитику не делаем.

### 9.4 Метрики расширения

К метрикам §6 добавляются: доля клиентов, подключивших второй источник (коллтрекинг или CRM), и время на подключение; время до первой находки о потерянном обращении; ложные срабатывания по обращениям (например, «пропущен, но перезвонили с другого номера»); доля пропущенных без перезвона за 24 ч до и после — в штуках; число платящих, отдельно по тарифам.

**Гипотеза для проверки:** не меньше 3 из 10 пилотных клиентов подключают второй источник и принимают хотя бы одну находку о потерянных обращениях; иначе этап 2 уходит в бэклог.

### 9.5 Открытые вопросы

1. Состав и цены тарифов Бизнес и Премиум.
2. Порядок продаж по сегментам. Рекомендация исследования: сначала агентства, собственник получает отчёт о потерянных обращениях через агентство; прямой выход к собственникам — по результатам пилота.
3. Передача текстов объявлений в YandexGPT расширяет правило «в LLM только обезличенные агрегаты» — нужна правка AI_GOVERNANCE и проверка юриста.
4. Формулировки на сайте: «покажем оценку ≈ N ₽», «найдём пропущенные звонки»; не «сэкономим», не «вернём клиентов»; «AI-аналитик» — только после подключения нейросети.
