# Объём версий AdPilot — канон

> Решения P0 (D1–D18) приняты владельцем продукта 2026-10-02; объём v1.0 сужен решением того же дня — [STRATEGY.md](STRATEGY.md). Этот файл — главный перечень границ: **что входит в какую версию**. Другие документы описывают, *как* это устроено, и на объём ссылаются сюда.

## 1. Иерархия документов

| Порядок | Документ | Отвечает на вопрос |
|---|---|---|
| 1 | [STRATEGY.md](STRATEGY.md) | тезис, сегменты, обещание v1.0, набор правил (3 базовых + расширение) — верх иерархии |
| 2 | **VERSION_SCOPE.md** (этот файл) | что в какой версии — канон по объёму |
| 3 | [PRD.md](PRD.md) | что делаем и зачем, сценарии и продуктовые правила |
| 4 | [ARCHITECTURE.md](ARCHITECTURE.md) | как устроена система |
| 5 | [DATA_MODEL.md](DATA_MODEL.md) | таблицы, состояния, инварианты |
| 6 | [API_CONTRACT.md](API_CONTRACT.md) (v1.0) · [API_CONTRACT_EXECUTION.md](API_CONTRACT_EXECUTION.md) (v1.1) | контракт frontend ↔ backend; write-модель исполнения — отдельно |

Специализированные документы детализируют темы и подчиняются цепочке выше: [PRODUCT_SPEC.md](PRODUCT_SPEC.md) (пять принципов как требования, UX-паттерны и критерии готовности экранов v1.0), [EXECUTION_SAFETY.md](EXECUTION_SAFETY.md) (контур исполнения, **v1.1**), [AI_GOVERNANCE.md](AI_GOVERNANCE.md), [ECONOMICS.md](ECONOMICS.md), [DISASTER_RECOVERY.md](DISASTER_RECOVERY.md), [LEGAL.md](LEGAL.md).

**Выжимки** — `_docs/project.md`, `_docs/stack.md`, `PRODUCT.md`. Короткие и могут отставать; при расхождении правы первоисточники.

Правила:
- Изменение объёма v1.0 или списка правил начинается с STRATEGY.md, затем — этот файл.
- Расхождение по объёму между документами ниже STRATEGY.md → прав этот файл; остальные исправляются.
- Новая функция попадает в версию только строкой здесь. Нет строки — функция не запланирована.
- Метки в тексте документов: **[v1.0]**, **[v1.1]**, **[v2.0]**; архитектура исполнения в технических документах помечается «Deferred to v1.1».

## 2. Словарь: что значат слова в v1.0

| Слово | В v1.0 | Не означает в v1.0 |
|---|---|---|
| **Применить / выполнить** | человек вручную вносит изменение в интерфейсе Директа и отмечает «Выполнено вручную»; AdPilot фиксирует исходное состояние и сверяет выполнение по данным Директа (чтение) | запись в кабинет через API, кнопку «Применить» |
| **Решение** | «Принять к выполнению» · «Проверил» · «Позже» · «Не буду» (с причиной) — одним участником с правом decide | одобрение, кворум, уровень риска как условие записи |
| **Автоматизировать** | автоматические только чтение, аудит, сверка, замер и оповещения | автоматические изменения в кабинете — v2.0 |
| **Откатить** | человек вручную возвращает значение в Директе, опираясь на исходное состояние, которое AdPilot зафиксировал при ручном выполнении | механизм отката через API — v1.1 |
| **Предпросмотр** | «что сейчас по снимку · что поставить · где это в Директе» как инструкция для ручного выполнения | предпросмотр «было → станет» для применения через API — v1.1 |
| **AI** | объяснение конкретной рекомендации — «Почему AdPilot так решил»; ответы только по проверенным находкам; Chief Analyst и отраслевые ИИ-специалисты (только чтение, над пакетом доказательств) | агенты, меняющие кабинет; свободные рассуждения LLM с новыми числами |

## 3. v1.0 — входит

### 3.1 Продукт

| Что | Где описано |
|---|---|
| Яндекс.Директ (N кабинетов в workspace) + Яндекс.Метрика через OAuth — только чтение данных, не вход | PRD §4 · ARCHITECTURE §2.6–2.8 |
| Снимки данных, ежедневный аудит, свежесть данных и здоровье интеграций | PRD §2, §4 · ARCHITECTURE §4 |
| **Три базовых правила:** нулевые конверсии · высокий CPA (target / baseline) · площадки РСЯ без конверсий. **Расширение (2026-10-09):** поисковые запросы без конверсий · аномалии расхода и конверсий; недоиспользование бюджета — если останется время. Каждое — только с golden evals | STRATEGY §3 · PRD §4 |
| Детерминированные аналитические движки по отраслям создают факты и находки; Chief Analyst и отраслевые ИИ-специалисты (только чтение) работают над пакетом доказательств; «Спросить AI» только по проверенным находкам | STRATEGY §4 · AI_GOVERNANCE §1 · INTELLIGENCE_V2_CONTRACTS |
| Приоритизация; итог «Расход с признаками неэффективности ≈ N ₽» без двойного учёта | PRD §4 · ECONOMICS |
| Рекомендации с доказательствами и «Почему AdPilot так решил»; уверенность по правилу; политика безопасности | PRD §2, §5 · AI_GOVERNANCE §2 |
| Решение человека и ручная фиксация действия; причины отклонения | PRD §5 · API_CONTRACT §3–4 |
| Фиксация исходного состояния, сверка ручного выполнения по данным Директа | PRD §5 · API_CONTRACT §3 |
| Замер эффекта через 7 дней, «Сэкономлено ≈» по подтверждённым выполнениям | PRD §1 · ARCHITECTURE §5 |
| Экран «Сегодня» (ответ за 5 секунд), Рекомендации, Аналитика, Настройки | PRD §5 |
| Оповещения по email и в кабинете без названий клиентов, кампаний, запросов, логинов (Telegram не используется, решение 2026-10-09) | PRD §2, §5 · ARCHITECTURE §8 |
| Агентства: организация, клиентские workspace, команда, роли | PRD §5 · API_CONTRACT §10 |
| 7 дней бесплатного доступа, затем подписка; честный биллинг (решение 2026-10-09) | PRD §7 · ARCHITECTURE §7.3 |

Статусы рекомендации v1.0: `new` → `requires_decision` → `accepted` → `applied` (`execution_mode = manual`, сверка `verification_status`) → замер; а также `postponed`, `rejected` и «Проверил» (`applied`, `execution_mode = none`) для `inspect_only`. Подробно — PRD §5.

## 7. Открытые вопросы по объёму

1. **Запуск регистрации по SMS** — HOLD до заключения юриста по 149-ФЗ (LEGAL.md, PRD §10 №13). Если порядок не подтвердится — запасной вариант D2: вход через Яндекс ID (уже в коде); перенос его в v1.0 — решение владельца.
2. **Не названы в решении 2026-10-02:** раздел «Аналитика», «Что изменилось за сутки», «Почему цифры отличаются?», утренний дайджест и недельный отчёт в Telegram. Оставлены в v1.0 по PRD; если не укладываются в недели 2–4 плана — первыми переносятся «Почему цифры отличаются?» и недельный отчёт (PRD §9). Подтвердить.
3. **Пороги «достаточного объёма данных»** для правил «Нулевые конверсии» и «Площадки РСЯ без конверсий» — в спецификации rule engine, ещё не зафиксированы.
4. **Идеи без версии** (PRD §6): рейтинг здоровья рекламы, AI-контроль подрядчика, настройка порогов готовых правил.
5. **Напоминание о списании без email** (PRD §10 №15): канал для пользователя без email и Telegram не решён.
