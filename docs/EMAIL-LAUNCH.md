# Подключение регистрации по почте для inrou

Подготовлено 21.10.2026. Форма регистрации и серверные операции уже реализованы. Для реальных писем нужен аккаунт отправителя, подтверждённый домен, ключ и опубликованные документы. До настройки вход по почте выключен, поля не принимают ввод и отправка не имитируется.

## Выбранный транспорт

Unisender Go, российский HTTPS endpoint. Существующий SMTP также сохранён для совместимого хостинга. Тариф Unisender Go нужно проверить в своём кабинете; бесплатный маркетинговый тариф другого продукта Unisender не означает бесплатный транзакционный API. Оплата и новые аккаунты этим изменением не создавались.

Официальные источники:

- API: https://godocs.unisender.ru/web-api-ref — `POST https://goapi.unisender.ru/ru/transactional/api/v1/email/send.json`, ключ в `X-API-KEY`.
- Домен и доставляемость: https://godocs.unisender.ru/delivery-assurance — подтверждение владения доменом, SPF и DKIM; также настройте DMARC.
- Размещение сервиса: https://www.unisender.com/ru/features/email/unisender-go-email-smtp-api/ — поставщик заявляет серверы в России. Условия обработки данных проверяются при заключении договора.
- Render Free: https://render.com/docs/free — исходящие SMTP-порты 25/465/587 заблокированы. HTTPS-транспорт не использует эти порты.

## Что нужно сделать в аккаунте владельца

1. Открыть https://go.unisender.ru/ и создать аккаунт на рабочую почту владельца. Владелец принимает договор и подтверждает почту сам.
2. Добавить собственный домен и адрес отправителя, например `noreply@<ваш-домен>`. Домен `onrender.com` принадлежит Render: подтвердить его как свой нельзя.
3. Добавить в DNS записи владения, SPF, DKIM и DMARC по значениям из кабинета провайдера. Не копировать выдуманные DKIM-ключи из примеров. Дождаться успешной проверки.
4. Получить проектный API-ключ с отправкой писем. Ограничить квоту и доступ, если кабинет предоставляет такие настройки.
5. В панели **российского хостинга** сохранить параметры ниже. Секреты не присылать в чат и не включать в Git. Текущий Frankfurt-стенд остаётся без регистрации реальных клиентов до подготовки российского размещения.

```dotenv
REKVERO_EMAIL_ENABLED=true
REKVERO_MAIL_PROVIDER=unisender
REKVERO_MAIL_API_KEY=<секретный API-ключ проекта>
REKVERO_SMTP_FROM=<подтверждённый адрес отправителя>
REKVERO_EMAIL_ORIGIN=https://<публичный-домен-inrou>
REKVERO_AUTH_HMAC_KEY=<криптографически случайный секрет не короче 32 байт>
```

`REKVERO_EMAIL_ORIGIN` должен точно входить в `API_ALLOWED_ORIGINS`. Несмотря на имя `REKVERO_SMTP_FROM`, это адрес отправителя и для HTTPS API. SMTP-хост, логин и пароль для режима `unisender` не нужны. Ключ и адрес не попадают во frontend JavaScript.

6. Заполнить и опубликовать реквизиты и правовые документы. `API_SIGNUP_APPROVED_HASHES` заполняется хешами окончательных документов; нельзя утверждать технические заглушки для обхода блокировки.
7. После перезапуска проверить с отдельной тестовой почтой: регистрация → настоящее письмо → подтверждение → новый кабинет → выход → повторный вход → восстановление пароля. Проверить папку «Спам», подписи и срок действия ссылок. После подтверждения отдельно подключается Директ.

## Реализованные ограничения

- Подтверждение и восстановление используют одноразовые ссылки; аккаунт не считается подтверждённым до проверки ссылки и пароля.
- API отправки имеет фиксированный адрес, TLS, таймаут 10 секунд и не следует редиректам с ключом.
- Ошибка провайдера превращается в нейтральную ошибку; ответы с ключами и адресами не выводятся клиенту.
- Ссылки подтверждения не переписываются трекером: `track_links=0`, `track_read=0`.
- Нет автоматического перехода на другой транспорт при ошибке. Лимиты попыток регистрации и входа сохраняются.

Номер телефона не запрашивается: основным вариантом выбран email. SMS-провайдер, платная отправка и новая обработка телефонных номеров не подключались.
