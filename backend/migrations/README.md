# Миграции схемы

Простой SQL-раннер (`__init__.py`, ~100 строк, зависимость только `psycopg`). Схема пишется на чистом SQL
(CHECK, триггеры, RLS, гранты, SECURITY DEFINER), ORM нет, поэтому автогенерация Alembic здесь ничего не даёт,
а сам Alembic тянет SQLAlchemy и Mako. Если позже появится SQLAlchemy, журнал `schema_migrations` переносится
в Alembic одной миграцией-заглушкой.

## Правило

**Любое изменение схемы = новая миграция в `versions/` + та же правка в `backend/db/schema.sql` + строка в
`released.txt`.** `schema.sql` остаётся полной текущей схемой (по ней пишут тесты и читают её люди), миграции
дают воспроизводимый путь от пустой БД и от любой выпущенной версии. `tests/test_migrations.py` ловит
расхождение: накатывает все миграции на пустую БД и сравнивает каталог PostgreSQL (таблицы, колонки, ограничения,
индексы, функции, триггеры, политики RLS, гранты, default privileges) с БД, созданной из `schema.sql`.

Выпущенные миграции неизменны: раннер хранит sha256 каждой версии в `schema_migrations` и откажется работать,
если файл применённой версии изменён; тест сверяет файлы с `released.txt`.

## Как добавить миграцию

1. Создать `versions/0002_short_name.sql` (номер — следующий по порядку, имя — `[a-z0-9_]`). Миграция
   выполняется в одной транзакции, поэтому без `CREATE INDEX CONCURRENTLY` и подобного.
2. Внести ту же правку в `backend/db/schema.sql`.
3. Запустить `pytest tests/test_migrations.py`: тест назовёт sha256 новой версии — добавить строку
   `0002_short_name <sha256>` в `released.txt`.
4. Повторить тест: каталоги совпадают — изменение согласовано.

Большую версию можно разложить на каталог `versions/NNNN_name/` с файлами `01_*.sql`, `02_*.sql`, … (≤ 500 строк
каждый): они склеиваются по имени и применяются одной транзакцией. Так устроен снимок `0001_baseline` —
побайтная копия `schema.sql` на коммите `bd03698`.

## Применение

```bash
cd backend
MIGRATION_DATABASE_URL=postgresql://app_migrator@host/db python -m migrations
```

Роли `app_migrator`, `app_rw`, `app_token`, `app_system`, `app_deleter` создаются на уровне кластера заранее
(как в `tests/conftest.py`). Одновременный запуск двух миграторов безопасен: advisory-блокировка на транзакцию.
