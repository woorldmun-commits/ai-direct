# ai-direct — бизнес-контекст

Источник: `docs/STRATEGY.md` (решение владельца 2026-10-03, верх иерархии по объёму и правилам), `docs/PRD.md` v1.0. Выжимка для спек; при расхождении правы первоисточники, по объёму версий — канон `docs/VERSION_SCOPE.md`.

## Что это
AdPilot — независимая AI-система управления рекламой, которая говорит только проверяемую правду. Клиент подключает Яндекс Директ и Метрику → AdPilot проверяет качество данных → находит проблемы и точки роста → AI-аналитик объясняет → человек решает → AdPilot измеряет эффект.
Принцип **TRUTH FIRST** (STRATEGY §2): никаких выдуманных, заполненных нулём или скрытых данных; `"--"` ≠ 0; оценка ≠ факт; Факт → Расчёт → Вывод → Рекомендация.

## Кто клиент
Одна платформа, три режима UX: собственник бизнеса, маркетолог / директолог, агентство (STRATEGY §3).

## Ровно три правила v1.0
1. Нулевые конверсии. 2. Высокий CPA (target / baseline). 3. Площадки РСЯ без конверсий. Рекомендации работают и при автостратегиях и ЕПК. Новое правило — только через `docs/STRATEGY.md`.

## Принятые решения (не противоречить в спеках)
- Цикл v1.0: данные → Truth Layer и Data Health → rule engine → доказательства → «Почему AdPilot так считает?» → рекомендация → AI-аналитик объясняет → решение человека → ручное выполнение → сверка по данным Директа → замер через 7 дней.
- Статусы рекомендации v1.0: `new` → `requires_decision` → `accepted` → `applied` (`execution_mode = manual`, сверка) → замер; `postponed`, `rejected` (с причиной); «Проверил» — `applied`, `execution_mode = none`.
- Числа считает детерминированный код. AI-аналитик (v1.0, только чтение) отвечает только из `AnalysisContext` текущего workspace через валидатор; не меняет рекламу и не считает деньги.
- «Расход с признаками неэффективности ≈ N ₽» — оценка, одна сумма учитывается один раз. «Сэкономлено ≈» — только по выполненным и подтверждённым сверкой рекомендациям, `estimated`, до/после 7 дней без контрольной группы. Не «потеряно», не «возвращено», не «заработано».
- Кабинет: Анализ (главный) · Рекомендации · Эффект · Подключения · Настройки; Data Health — постоянный статус-бар.
- Честный биллинг, без тёмных паттернов (PRD §7).

## Roadmap
- **v1.0:** Директ (N кабинетов) и Метрика, Truth Layer, Data Health, три правила, итог без двойного учёта, доказательства, AI-аналитик read-only, решение и ручное выполнение со сверкой, замер, уведомления, роли, бесплатный аудит + подписка. Вход — номер телефона + SMS (включается после юриста; до этого — Яндекс ID, `docs/LEGAL.md`).
- **v1.1:** безопасное API-исполнение отдельным контуром (права, idempotency, лимиты, журнал, approval flow, откат, kill switch — `docs/EXECUTION_SAFETY.md`), участие AI в действии, офлайн-конверсии (CSV).
- **v2** CRM · **v3** VK Реклама · **v4** маркетплейсы · **v5** автопилот по разрешённым правилам.

## Текущий этап и критерии готовности
План до первого клиента — `docs/STRATEGY.md` §10 (≈ 9 недель): P0 (права БД, `"--"` ≠ 0, CPA на днях досчёта, деление на ноль, видимые сбои синка) → вход и OAuth → воркер и Data Health → кабинет на реальном API → AI-аналитик → деплой → первый клиент.
v1.0 готова, когда на живых кабинетах работает повторяемый цикл: находка → доказательство → решение → ручное выполнение → сверка → замер. Метрики пилота — STRATEGY §9.
