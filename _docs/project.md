# ai-direct — бизнес-контекст

Источник: `docs/STRATEGY.md` (решение владельца 2026-10-02, верх иерархии по объёму и правилам), `docs/PRD.md` v1.0. Выжимка для спек; при расхождении правы первоисточники, по объёму версий — канон `docs/VERSION_SCOPE.md`.

## Что это
AdPilot — доказательный контроль рекламного кабинета Яндекс.Директа с обязательным решением человека. Не «AI решит за вас», а «AdPilot обнаружит проблему, докажет её на данных и проведёт решение через человека».
Обещание v1.0: выявляем риски и возможности, объясняем их и помогаем принять контролируемое решение; изменения в кабинете вносит человек вручную. Автоматический рост эффективности не обещаем.
Оффер: «Подключите Яндекс.Директ за 2 минуты — покажем, где рекламный бюджет расходуется неэффективно».

## Кто клиент (сегмент v1.0)
Малые агентства и самостоятельные директологи: несколько кабинетов у одного специалиста, понимают метрики, агентство — канал к собственникам. Собственник бизнеса — не целевой сегмент v1.0.
Работа пользователя: понять, где бюджет расходуется неэффективно или недоиспользуется → увидеть доказательство → решить → вручную изменить в Директе → проверить эффект.

## Ровно три правила v1.0
1. Нулевые конверсии. 2. Высокий CPA (target / baseline). 3. Площадки РСЯ без конверсий. Рекомендации работают и при автостратегиях и ЕПК. Новое правило — только через `docs/STRATEGY.md`.

## Принятые решения (не противоречить в спеках)
- Цикл v1.0: данные → rule engine → доказательства → «Почему AdPilot так решил» → рекомендация → решение человека → ручное выполнение → фиксация и сверка по данным Директа (чтение) → замер через 7 дней.
- Статусы рекомендации v1.0: `new` → `requires_decision` → `accepted` → `applied` (`execution_mode = manual`, сверка) → замер; `postponed`, `rejected` (с причиной); «Проверил» — `applied`, `execution_mode = none`.
- Числа считает детерминированный код, LLM только объясняет конкретную рекомендацию (claims → evidence). Общего чата в v1.0 нет.
- «Расход с признаками неэффективности ≈ N ₽» — оценка, одна сумма учитывается один раз. «Сэкономлено ≈» — только по выполненным и подтверждённым сверкой рекомендациям, `estimated`, до/после 7 дней без контрольной группы. Не «потеряно», не «возвращено», не «заработано».
- «Сегодня» отвечает за 5 секунд: сколько ≈, сколько проблем, 3 действия; у каждой цифры — «Факт / Оценка ≈ / Недостаточно данных».
- Честный биллинг, без тёмных паттернов (PRD §7).

## Roadmap
- **v1.0:** чтение Директа (N кабинетов) и Метрики, три правила, итог без двойного учёта, доказательства, решение и ручное выполнение со сверкой, замер, центр уведомлений + email-дайджест (Telegram не используется), агентства и роли, бесплатный аудит + подписка. Вход и регистрация — только по номеру телефона + SMS-код; email — контакт для чеков, безопасности и дайджеста; Яндекс OAuth — только подключение Директа и Метрики (юридическая обвязка — до публичного запуска, `docs/LEGAL.md`). Резерв v1.1+: Яндекс ID / VK ID, Web Push.
- **v1.1:** безопасное API-исполнение отдельным контуром (права, idempotency, лимиты, журнал, approval flow, откат — `docs/EXECUTION_SAFETY.md`), офлайн-конверсии (CSV), «Спросить AI» только для чтения.
- **v2.0:** Outcome Graph, автоматизация по заранее одобренным правилам, CRM, VK Реклама.

## Текущий этап и критерии готовности
План 6 недель, сейчас **неделя 1**: CI, миграции, security headers, каркас FastAPI, RLS + actor из сессии, включение SMS-потока + защита от абуза (капча, блок VoIP, лимиты), тесты изоляции. Далее: 2–3 — три правила и «Сегодня»; 4 — решение, ручное выполнение, сверка, замер, центр уведомлений + email-дайджест; 5 — бесплатный аудит, оплата, юридические тексты; 6 — пилот на 10 агентствах.
v1.0 готова, когда на живых кабинетах пилота работает повторяемый цикл: находка → доказательство → решение → ручное выполнение → сверка → замер. Метрики пилота: time to first finding, acceptance rate, rejection reasons, false-positive rate, free-to-paid, хотя бы один подтверждённый измеренный результат.
